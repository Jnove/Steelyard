# 筑衡产品流程与界面设计交付

这份目录保留工业设计交付的原型、素材与交接说明。`prototype/` 是独立设计快照；三种对比视图已经移植到正式 React 看板，见 [前端接入说明](../docs/design-comparison-integration.md)。设计快照与当前正式评估结果可能不同，均不能替代专业结论。

## 一句话说明任务

让首次接触项目的人在一次演示中看懂：**哪些方案不能选、剩余方案各有什么取舍、为什么当前视角下推荐某个方案**。

## 第一阶段：流程与线框（优先完成）

交付物是可点击的 [低保真流程原型](prototype/index.html)、[二维方案对比视觉稿](prototype/comparison.html) 和以下页面决策。浏览器直接打开 HTML 文件即可查看；不需要 Figma 账号。对比视觉稿使用仓库现有的虚构评分与四个角色权重，演示图表、排名与合规提醒的布局。下载时保留同目录下的 CSS、JS 与数据文件。

### 二维方案对比稿 V6 · 玻璃材质与指标网格

按用户提供的 [UI 素材手册](resources/liquid-glass/Steelyard_UI_Resource_Guide.md) 调整了对比原型。静态蓝紫 / 淡粉柔光、20px 模糊、半透明白面板、白色边缘高光构成统一材质；方案点使用 SVG 径向渐变，双方案连线使用透明渐变色带。数字和坐标仍以深色呈现。密集表格使用浅色实底，固定表头、首列滚动时不会透出下面的文字。

V5.1 针对用户反馈的“只有方案点变化明显”强化整张面板：主玻璃底色从白 / 62% 调为白 / 36%，叠加局部高光；增强蓝紫、青色与淡粉背景；工具栏和坐标 / 方案选择区使用独立的浮起玻璃条；图表底板、详情卡与表格容器增加边缘亮线及投影。SVG 图内也加入反光带和渐变边线。见 [相同数据的前后对照](evidence/comparison-glass-before-after.png)。

V6 针对总表内部变化不明显的反馈重做指标网格：[直接进入总表](prototype/comparison.html#view=matrix)。方案表头变成带字母标识、名称与排名的独立卡片；汇总格与指标格使用不同底色和间距；数字格增加圆角、白色亮边及内凹进度轨道；B 列加入粉色斜纹；选中格与对应方案表头使用方案色描边。固定表头 / 首列仍隔离下面的文字，不对每格叠加 blur。导出 SVG 同步改为卡片网格。见 [总表自身的前后对照](evidence/comparison-matrix-before-after.png)。

材质集中在 [comparison-glass.css](prototype/comparison-glass.css)，便于前端映射到现有 Ant Design / ECharts。它实现毛玻璃与绘制高光，没有采用真正的位移折射。导出 SVG 自带背景、渐变和字体配置，离线打开即可显示；无模糊支持或减少透明度设置时使用实底。具体参数和开发映射见 [玻璃风图表交接](glass-chart-handoff.md)。

当前阅读顺序为 **看整体 → 比两套 → 查全表**。默认打开二维取舍图；从选中方案旁的按钮进入双方案比较；需要完整评分和规则依据时再打开矩阵。保留原生 SVG 作为无需安装依赖、可离线打开的设计原型，正式前端可映射为现有 ECharts 5.x 图表。

- **指标工作台**：“查全表”现在按当前排名排列方案，提供方案勾选、指标/规则搜索和维度筛选；四个汇总维度可展开八项指标。颜色和短条辅助读数，主体是清楚的分数、原始输入和选中状态。
- **比较基准**：“看得分”与“看与基准的差距”可切换。基准通过选择框指定，每一项指标和维度都以原始得分做差，最后舍入。负数、零、缺数据分别呈现，选择或清空搜索不丢失焦点。
- **分数追溯**：点击后在同一工作区右侧查看输入、评分曲线、相对权重与来源。汇总维度可以继续点开具体指标。手机和平板使用原生 dialog 抽屉，支持 Escape 关闭并恢复原格子的焦点；键盘方向键在表格内移动时保持页面位置。
- **合规检查**：独立切换到四条硬约束，分别显示通过、未通过、不适用和数据不足。点击状态可查看实际值、条件、严重程度和表达式。B 可以作评分参考，但始终提示它不参与默认排名。
- **二维取舍图**：自由选择横纵轴，所有坐标使用 0–100 分；选择重复维度时自动交换两轴。每个点代表一套方案，点的位置只反映选定的两个维度，不能代替四维加权排名。
- **四维非劣标记**：双环直接读取角色排序快照的 `is_non_dominated`，不从二维点的位置推算。点旁标出方案名称，选中方案显示四维分数、当前排名与对比入口。可展开非劣含义。
- **双方案差值图**：两套方案可自由选择与交换，四个维度分别显示两个端点、连接线和带正负号的差值。端点重合用双层圆标记，表示分数相同。差值由未舍入的维度分数相减后显示，缺值不填为零。图旁小结说明哪方在哪些维度得分更高及最大差距。B 可以作参考对比，但会明确提示其不参与默认排名。
- **违规方案**：矩阵中 B 列用斜纹与文字区分，不参与默认排名；坐标图默认不显示 B，可以单独勾选显示。它的分数来自评估快照，未用零分代替违规状态。
- **角色切换与导出**：切换角色同步更新权重和贴近度，维度分数与坐标保持不变。当前视图可导出独立 SVG，适合放进设计评审材料。

页面不依赖远程字体、第三方 CDN 或后端服务。运行 `node design/sync-comparison-data.cjs` 可从仓库快照更新原型数据，不需复制或手填专业数值。

当前验收覆盖真实快照中的原始指标值、搜索/空结果、维度展开与方案筛选、指标/维度基准差值、键盘焦点和滚动位置、合规与缺项状态、导出失败后重试，以及 320/375/414/768px 的布局和抽屉关闭后的焦点恢复，无页面运行时错误。新增合规查询和分差 SVG，与原来的三种图一起完成下载与解析检查。

展示素材：[取舍图页面](evidence/comparison-map.png)、[双方案页面](evidence/comparison-pair.png)、[指标工作台](evidence/comparison-matrix-panel.png)、[分差与评分曲线](evidence/comparison-matrix-difference.png)、[合规查询](evidence/comparison-compliance.png)。可直接查看或导入设计软件的矢量图：[取舍图 SVG](evidence/comparison-map.svg)、[双方案 SVG](evidence/comparison-pair.svg)、[指标查询 SVG](evidence/comparison-matrix.svg)。均为政府视角的虚构示例。

### 开发交接

| 设计块 | 数据来源 | 正式前端建议 |
| --- | --- | --- |
| 二维取舍图 | `/rank` 的维度分数；非劣标记读取 `is_non_dominated`；身份用 `scheme_id` | ECharts `scatter`，固定 0–100 坐标刻度；方案名称、悬浮提示及选中状态联动 |
| 双方案差值图 | 按 `scheme_id` 取得两套方案的原始维度分数 | ECharts 自定义系列或端点散点配合连接线；不对显示出来的舍入值做差 |
| 指标与依据工作台 | `/evaluate` 的分数、指标、合规和缺项状态；`/api/rules` 的评分分段；`/rank` 的角色权重与名次 | Ant Design Table 的固定表头、树形展开、搜索和选择；桌面侧栏与窄屏 Drawer 接入 `TraceDrawer` |
| 导出及结论 | 同一份已返回结果；明确当前角色与方案范围 | SVG 导出；结论文本只复述已核验差异 |

主说明文字使用 13–15px，关键分值使用 18–34px；评分公式放入可展开详情。本次参考 Hallmark 的交互与微交互章节，增加明确的默认/选中/焦点/按下/禁用反馈，导出具备处理中、失败和成功提示；切换和选中只用短时透明度反馈，支持减少动态效果。视觉借鉴及取舍见 [参考资源记录](references.md)。

| 步骤 | 用户要解决的问题 | 页面必须说清楚的内容 | 建议组件 |
| --- | --- | --- | --- |
| 1. 方案录入 | 比较哪些方案？ | 项目条件与方案条件分开；字段单位、必填项、缺项提示；手动录入和 Excel 导入入口 | Form、Steps、Alert、Upload |
| 2. 合规检查 | 哪些方案存在硬约束问题？ | 通过/警告/不通过三种状态；规则 ID、实际值、阈值、出处；错误级不通过方案默认不参与排名 | Alert、Tag、Table、Drawer |
| 3. 多方案比选 | 谁领先，取舍在哪里？ | 当前角色、第一名、参与排名的方案、四维差异、分数溯源入口 | Card、Table、Progress、ECharts |
| 4. 角色与权重 | 换个视角会怎样？ | 四类角色、四维权重、排名及贴近度变化；自定义权重与预设角色明确区分 | Segmented、Slider、ECharts |
| 5. What-if | 改一个参数会怎样？ | 修改前值、新值、原方案与副本、重新计算后的指标和名次变化 | Form、Descriptions、Table |
| 6. 最终报告 | 如何向他人说明决定？ | 结论、合规问题、四维取舍、稳健性、修改建议、可追溯入口和导出 | Typography、Anchor、Drawer |

信息顺序建议：**结论 → 整体取舍 → 两套方案的具体分差 → 完整数据与依据**。首次进入比选看板时，二维取舍图作为主画面；双方案差值图解释细节，热力矩阵负责完整查询。

### 第一阶段完成标准

1. 不读项目文档的人能独立走完六步，并说出“B 为什么不参与排名”。
2. 每一屏有明确的主操作；错误、警告和普通信息不会混淆。
3. 任何排名都能看到当前角色或权重；任何分数都能找到原始值和依据。
4. 开发同学能把每个设计块对应到现有 Ant Design/ECharts 组件和后端数据。

## 第二阶段：界面视觉与开发交接

在第一阶段通过团队讨论后，定一套可复用的视觉规范：颜色与状态色、字体层级、间距、按钮、卡片、表格、图表线色和图例、空状态、加载与错误状态。交付桌面端关键页面和窄屏布局，并为违规提示、分数溯源、报告数字异常等重要状态单独出图。高保真稿先与前端同学确认可用组件，再落实到现有页面。

交接时给出每个页面的操作说明、文案、数据字段、状态图和需要开发修改的优先级。工业设计负责用户理解与视觉表达；建筑和土木专业组负责规则阈值、权重、条文出处，前端负责接入真实计算与交互。

## 第三阶段：演示与答辩材料

按不超过五分钟的故事线准备视频脚本、录屏、字幕与剪辑：场景和问题 → 录入及合规 → 方案比较 → 权重变化 → What-if → 报告与价值。同步统一答辩 PPT、技术架构图与界面的色彩和术语。脚本中的每个镜头必须能由当前可运行产品或明确标注的示例素材支撑。

## 当前原型与正式系统的边界

- 原型是静态演示页面；输入框和按钮用于讨论操作方式，**不会调用后端计算**。其中示例值不作工程依据。
- 当前仓库的四个预设角色在原始样例上的名次相同。若视频需要演示名次变化，可使用已有的自定义权重演示；若要展示角色切换即换位，需要专业组确认可用的新样例数据。
- 当前真实模式的 What-if 入口支持修改标准层重复率并创建副本；策划书里的“改用 MiC”需要另行确认数据和交互实现。
- T10 规范条文检索尚未完成；条文原文区域只能作为预留设计。现有规则、权重与方案有示例内容，专业组确认前不得将其作为真实工程验证或比赛结论。

## 建议的下一轮评审

请团队用原型走一遍六步，并分别记录：哪里看不懂、哪项信息应该先看到、哪一步缺少操作入口。前端同学核对组件与数据可实现性；专业组核对术语、违规说明和正式依据。根据反馈改线框，再进入高保真和视频脚本。
