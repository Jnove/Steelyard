## 逐省收条文的实际瓶颈（三种，按出现频率）

1. **正文拿不到**：地方标准多为推荐性 `DBxx/T`，全文 PDF 常在付费标准库；能免费拿到的是
   政府网站的通知页（只有印发语）或新闻报道（只有结论、没有条号）。
   → **这类省就空着**，接口里写"尚无已逐条核对原文的地方条文"。
2. **拿到正文但缺字段**：例如宁夏导则正文拿到了，但它要求的是"**净高** ≥3.0m""**人均**公共绿地"
   "阳台栏杆净高"——系统现有字段里是"层高""绿地率""栏杆"等**另一个量**，判不了。
3. **不是现行有效文本**：送审稿、征求意见稿、公示稿都不能当依据（青海、陕西就卡在这里）。

## 需要专业组拍板的**字段决策清单**

（加字段会牵动 schema / Excel / 前端类型，走一次生成链即可）：

| 候选字段 | 用它才能判的地方条文（举例） | 备注 |
| --- | --- | --- |
| `clear_height` 室内净高 (m) | 宁夏 4.x 起居室/卧室净高 ≥3.0m；多地住宅标准用"净高"而非"层高" | 与现有 `floor_height`（层高）是两个量，不能相互替代 |
| `per_capita_public_green` 人均公共绿地 (m²/人) | 宁夏 5.4-2（五分钟 ≥1.5、十分钟 ≥2.0） | 也可拆成两个按生活圈的字段 |
| `daylight_room_count` / `total_living_room_count` 居住空间数与获日照空间数 | 宁夏 4.x「至少 1 个居住空间获日照，4 个以上时至少 2 个」 | 现有 `sunlight_hours` 是"小时数"，口径不同 |
| `has_accessible_elevator` 是否设无障碍电梯 (是/否) | 宁夏 4.x「4 层及以上住宅的电梯应设无障碍电梯」 | 现有 `elevators_per_unit` 只是台数 |
| `corridor_window_floor_ratio` 门厅窗地比 | 宁夏 4.x「住宅门厅窗地比 ≥1/10」 | 与现有 `window_floor_ratio`（套内）不同部位 |

## 方法学说明（为什么"逐省核正文"这么慢）

- **检索代理读不了 PDF/Word**：会话内的 `web_fetch` 对 `application/pdf`、`.docx` 返回
  "unsupported content type"，代理所在的沙箱也不能出网下载。
- **正文核验由本地完成**：我用提权 shell 下载官方附件，再用 `pypdf` / `python-docx` 解析
  （浙江导则、青海 PDF、宁夏 DOCX 都是这样读出来的）。所以流程是：
  **代理负责找官方链接 → 我负责下载并逐字核对**。
- 因此每省的进度取决于"官方是否免费公开正文"，不取决于检索量。

## 收录纪律（重申，与设计文档一致）

1. **只收逐条核对过原文的**；`source` 写到条号/表号，可对照原文，并记核对日期；
2. **拿不到正文就空着**——空册是诚实状态，凭记忆或二手转述填数会毁掉整套规则的可信度；
3. **只有现行有效**的文本才能收（送审稿、征求意见稿、公示稿一律不收）；
4. 地方册**并联**国标、不替换；同一件事国标与地方都有规定时，两条都会出现在结果里。
