# 工业设计方案对比图接入

更新：2026-10-13。设计来源为 `zh/ui-design` 的 V6 原型，入口是 `design/prototype/comparison.html`。保留设计分支的提交历史、原型与交接素材；正式页面使用 React 组件和后端结果。

## 正式页面

项目的“对比看板”增加三个视图，沿用工业设计同学的阅读顺序和玻璃材质，并与主站的青绿、紫粉背景统一。

- **看整体**：横纵轴可切换，固定 0–100 刻度。选择重复维度时交换两轴。四维非劣标记来自后端；未参与排名的方案默认隐藏，可勾选作为参考。
- **比两套**：选择、交换方案，展示四维分数端点、原始分数的差值和对应小结。缺项不补零；参考方案显示明确提示。
- **查全表**：默认显示四个维度汇总，展开后查看当前指标。支持搜索、方案勾选、维度筛选、排序、基准分差和独立的合规查询。数字、真实零分、缺数据、不适用和规则失败分别呈现。

矩阵的桌面详情侧栏可继续打开评分溯源，查看原始输入、公式、评分曲线和出处。窄屏直接使用现有溯源抽屉；方向键在矩阵格子间移动，Escape 关闭抽屉并恢复焦点。

当前视图可导出独立 SVG，保留当前角色、权重、方案范围及参考提示。导出不依赖远程资源，项目名、方案名与规则文本均进行 XML 转义。

原来的权重滑杆、完整排名、雷达图、敏感性和名次概率保留；逐方案摘要放入可展开区域。

## 数据与边界

正式组件读取 `/evaluate` 的指标、合规状态、维度分数与覆盖率，以及 `/rank` 的名次、贴近度、实际权重和非劣标记；按 `scheme_id` 关联，不使用排序下标推断身份。角色来自现有接口，支持当前五个角色和自定义权重。

指标名称与行数由评估结果生成。验收时为 16 项评分指标和 19 条硬约束；没有把原型的旧示例数量写入正式组件。前端仅做展示、筛选和原分数的差值计算，不重算 TOPSIS 或规则判定。

`design/prototype/` 仍是独立的历史设计快照，不调用正式后端。其示例值与正式系统当前规则可能不同；更新正式规则时不应从设计快照复制数值。

评分、规则与专业出处仍按项目现有边界使用。图表接入不代表专业规则、真实模型或 T10 检索已经验收。

## 实现与验证

实现入口：`frontend/src/components/comparison/ComparisonWorkbench.tsx`；图表、SVG 导出与样式在同目录，数据关联和数值处理集中于 `frontend/src/utils/comparison.ts`。现有 `TraceDrawer` 承担详细溯源。没有新增运行依赖。

验证包括前端类型检查、生产构建和 67 项测试（其中 8 项新增测试覆盖身份关联、缺值、原数分差、动态规则与导出转义）。浏览器检查覆盖录入后评估、坐标轴交换、参考方案、角色联动、双方案交换、矩阵搜索与展开、基准分差、规则溯源、键盘焦点，以及 320 / 375 / 768px 下三种视图的布局。浏览器导出文件使用 XML 解析检查。

局部验收截图、导出文件与记录位于忽略目录 `backend/data/design-comparison-qa/`，不写入工程数据，也不替代专业验证。
