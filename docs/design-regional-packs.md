# 地区规则册（regional rule packs）

> 一句话：**国家层面标准永远生效；地方标准收进"册"里，默认关闭，由项目显式开启。**
> 这样既留住了地方条例这份资产，又不会让一套国标规则被迫背上某省的口径。

## 一、为什么这样做

地方标准与地方导则（DB33、《浙江省混凝土模块化建筑技术导则》等）在本地项目里是权威依据，
但它们**只在本省适用**：将来做别的省份或"个性化项目"时，套用外省条例是错的。
之前为了"只用国家层面标准"，把浙江的 MiC 高度/高宽比等规则**删掉**了——资产是丢了，
但问题并没有真正解决（下次要用还得重新核一遍原文）。

现在把它们**收进册**：默认不生效，需要时勾一下即可。

## 二、机制（三层）

| 层 | 位置 | 说明 |
| --- | --- | --- |
| **册代码与地区表** | `app/engine/regions.py` | `GB` + 大陆 **31 个省级行政区**；两字母地区码（内部约定）+ GB/T 2260 六位码（对外对齐） |

> 地区表的依据：[GB/T 2260 全国县及县以上行政区划代码表](https://tjj.jl.gov.cn/tjsj/tjbz/200805/t20080520_5118059.html)
> （吉林省统计局公布）。省级码取"两位省级序列 + 0000"，已抽样核对 110000 北京市 / 120000 天津市 /
> 130000 河北省与前缀序列一致；只收大陆 31 个，不含港澳台（71/81/82 开头）。
| **规则归属** | `RuleDef.pack` + 规则 ID | 国标：`S-14`（`pack` 默认 `GB`）；地方：`ZJ-S-01`（地区码 + 维度字母 + 序号，`pack` 必须与地区码一致） |
| **项目选择** | `ProjectParams.province` / `standard_packs` | `province` 是项目所在地；`standard_packs` 是启用的册，**留空＝只用 GB**，给了列表就必须含 `GB`（国标是底线，不允许关掉） |

**筛选**：`RuleSet.select_packs(codes)` 返回**新的**规则集（全局缓存的那份永远含全部册）。
评估入口 `POST /api/projects/{id}/evaluate` 按项目的册筛选后再跑——所以
**默认行为与以前完全一致**（只有 GB），开了地方册才会多出该省的规则。

**给前端的接口**（这是前端同学需要的一切）：

| 用途 | 接口 / 字段 |
| --- | --- |
| 渲染"适用标准"勾选框 | `GET /api/standards/packs` → 32 项（GB + 31 省）：`code` / `label` / `scope` / `rule_count` / `always_on` / `note` |
| 保存选择 | 项目层字段 `standard_packs`（列表）、`province`（单选），走现有的项目更新接口与 `/api/schema` 表单渲染 |
| 报告里标注来源 | `GET /api/rules` 的每条规则带 `id` 与 `source_file`；地方规则的 ID 自带地区码，无需额外字段就能分辨 |

`GET /api/standards/packs` 只读、不需要新表、也不改变任何现有接口的语义。

## 三、收录纪律（重要）

1. **只收逐条核对过原文的条文**。`source` 要写到条号/表号，数值要能对照原文；
   不凭记忆、不用二手转录。拿不到原文的册**就空着**——`rule_count: 0` 是诚实的状态，
   接口里会写明"尚无已逐条核对原文的地方条文"。
2. **每册记录版本与核对日期**（写在规则文件的头部注释里，因为地方标准更新频繁）。
3. **不覆盖国标**：地方册是**并联**的，不是替换。同一件事若国标与地方都规定，
   两条都会出现在结果里，由专业组决定口径（冲突展示见下节的"未做"）。
4. **地方规则也进 git、过 CI**：和国标规则同一套 `check_rules` 校验，
   文件里不允许出现运行期保留前缀 `X-`。

## 四、怎么给一个新省加册

1. 在 `app/engine/regions.py` 里确认该省代码（已有 31 个，不必新增）；
2. 新建 `rules/<省码小写>_<主题>.yaml`（例如 `rules/js_green.yaml`），头部写清
   依据文件的**名称、文号、版本与核对日期**；
3. 每条规则：`id: JS-Y-01`（地区码 + 维度字母 + 序号）、`pack: JS`、`source` 写条号与原文要点；
4. 跑 `python scripts/check_rules.py`（会校验 ID 形态、册与地区码是否一致、表达式与字段名）；
5. 跑 `python scripts/export_frontend_fixtures.py --grid-step 10` 刷新离线快照
   （CI 有一条"离线快照与当前规则一致"的检查）；
6. 提交。`GET /api/standards/packs` 里该省的 `rule_count` 会自动从 0 变成实际条数。

## 五、当前状态

- **GB 册**：全部国标规则（含 `rules/` 下原有的 33 条）。
- **ZJ 册（已收 4 条）**：`ZJ-S-01` MiC 混凝土 ≥C30、`ZJ-S-02` MiC 最大高宽比（提示）、
  `ZJ-S-03`/`ZJ-S-04` MiC 最大适用高度（6 度 / 7 度）——数值均由浙江省导则官方 PDF
  正文逐行核对。这四条原先散落在 `rules/structure.yaml`（编号 S-08/S-09）与已删除的
  `rules/structure_mic.yaml` 里，现在统一归册。
- **其余 30 个省**：空册（`rule_count: 0`），按上面的纪律"要用时再收"。

## 六、明确**没做**的事

- **冲突展示与法域提示**：目前不会提示"项目在江苏、却开了浙江册"，也不会把
  "同一件事国标与地方都规定"的情况分组展示。留待专业组定了口径再做。
- **地方册的评分指标**：现有 4 条浙江规则都是硬约束。若地方册要放**评分指标**，
  必须先定"与国标同维度指标如何计权"（项目里已有"重复计权"这条待办）。
- **覆盖全国 31 省的条文**：这是数据工作，不是代码工作。机制已就绪，
  按需按纪律收编。

## 七、与其它工作的关系

- **运行期覆盖层**（`docs/design-custom-add.md`）：地方册是**进 git 的权威内容**，
  与运行期草稿是两条路，不要混。界面临时加的规则仍走 `X-` 前缀 + 导出回灌。
- **土木侧规则核定**：另一条分支上把 S-08/S-09 删掉并重整了结构规则；
  本分支把这两条**迁进浙江册**（编号变 ZJ-S-03/04）。两边的删除动作一致，合并时应无冲突；
  若出现冲突，以"浙江内容只存在于 ZJ 册"为准。
