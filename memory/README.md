## 团队分工

团队为计算机（Jnove）、建筑、土木、工业设计四人。

| 成员 | 近期责任 |
| --- | --- |
| Jnove | 技术主线、前后端联调、专业规则接入、真实模型与部署验收、技术说明汇总、最终版本与提交材料核对 |
| 建筑 | 合规、居住品质、绿色相关规则与原文；政府 / 保障房平台和住户偏好；案例与专业结论核对 |
| 土木 | 结构、施工友好与工友安全规则；施工总包和开发企业偏好；调整前后结果复核 |
| 工业设计 | 基于现有页面完善体验路径与信息层级，制作架构图、storyboard 和视频，组织非专业用户走查 |

专业同学先整理规则清单和依据，不以大量 YAML 为近期目标；技术组统一维护新增字段及生成产物。各成员的人机协同履历写真实经历，不把模板示例或 AI 完成的检查记为本人完成。

## 不变的约束

- 不编造规范、条文号、阈值、行业数据与成效，未经专业核对保留 `TODO(专业组)`。规范、地块条件与专业经验需说明各自来源及适用范围。
- 数值由确定性引擎产生，模型负责理解、编排和解释。数据覆盖率、AHP 一致性和部署成功均不表示工程合规或结构安全已验证。
- 虚构方案可清楚标注后用于工作流演示，不能作为真实项目、工程验证或专业成效证据。
- 偏好切换后名次可能不变，按实际结果讲解；What-if 创建副本，原方案保持不变。
- 字段元数据集中维护，前端 / Excel 由模型生成；前后端以现有 REST / SSE 协议对齐。
- 冻结后只处理必要修复；若代码、规则或案例改变，同步核对部署、视频、报告和说明文档。
